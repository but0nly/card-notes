主要分为这三个层次
- *内存缓存*：最快的缓存层级
- *磁盘缓存*：最主要的缓存位置
- *service work cache*：一个更现代、可编程的缓存层。通过`JavaScript`代码控制，可实现离线访问等功能。

### 内存缓存
最显著的优点：
- *极速访问*：从内存中读取的速度比从硬盘中读取的要快得多。
- *非持久性*：当关闭浏览器或者当前会话页面就是被释放。

主要缓存资源：
- 视图内的小图
- 脚本执行后的变量（存在堆栈中）
- 解析完成的`CSS`

### 磁盘缓存
显著优点：
- 持久化：不会因为你关闭了浏览器或者重启电脑而被清空。
- 强缓存策略依赖；设置了长`max-age`的静态资源就是依赖这个持久性的磁盘缓存来完成。
  
管理问题：
1. 容量限制：通常是有一个容量上限，不会被无限制的占用空间。
2. 淘汰机制：*LUR*（遵循最近最少用），但是还会考虑另外两个因素：
	1. 资源的新鲜度：文件是否已经过期？
	2. 资源的成本：下载这个资源需要耗费多少带宽和时间？
	   

### Service Work Cache
像是一个运行在浏览器后台的**可编辑网络代理**，由开发者通过`JavaScript`来主动编写缓存逻辑。


**代理与离线能力**
***Service work***的能力是拦截网络请求，它坐在页面与实际网络之间，就像是一个守门员。

当你发起一个资源请求时，***Service work***可以：
1. *直接响应*：立即从它自己管理的**Storage**（跟http磁盘缓存不同）中返回资源
2. *网络请求*：允许进入网络请求。
3. *组合策略*：可以先网络请求，如果失败，再从缓存中拿。

优劣势
- **优势**：可以离线操作，没有网络也可以启动和运行。
- **劣势**：开发者必须要编写`JavaScript`来决定何时去请求实际网络获取数据。
两种不同的策略
- *缓存优先，后台更新*：始终立即从缓存中提供资源（速度极快），然后在后台异步检查网络是否有更新。
- *网络有限，缓存最后*：始终先尝试从实际网络中获取数据，如果网络失败或者连接慢，则回退到缓存。但是牺牲了==速度，即网络往返时间（RTT）==

*main.js*：主要注册**service worker**
```js
if('serviceWorker' in navigator){
  // 注册 Service Worker,告诉浏览器脚本在哪里
  navigator.serviceWorker.register('./sw.js')
  .then(reg => {
    console.log('Service Worker注册成功,作用域', reg.scope);
    fetch("https://example.com")

  })
  .catch(error => {
    console.log('Service Worker注册失败:', error)
  })
}
```

*sw.js*：缓存脚本：安装缓存和通过javeScript编写缓存逻辑
```js
// 缓存名称
const CACHE_NAME = 'try_v1';

// 需要缓存的文件路径
const urlsToCache = [
  // 离线缓存必须要填入 index.html和mian.js
  './index.html',
  './main.js'
]


// 因为是运行在独立于页面的后台线程中, 没有window对象, Service Worker必须使用全局关键字self来代表它自身.
// 监听intall
self.addEventListener('install', event =>{

  // 使用waitUntil来确保安装事件不会在所有文件都下载并存储之前完成.
  event.waitUntil(
    caches.open(CACHE_NAME) // 打开缓存
    .then(cache => {
      // 拿到缓存对象'cache';

      // 将所有文件路径都添加到缓存中
      return cache.addAll(urlsToCache)
    })
    .then(() => self.skipWaiting()) // 强制新的SW立即激活.
  )
})

/** 这里我们用缓存优先,网络更新的策略 **/
// 监听fetch
self.addEventListener('fetch', event => {
  // 拦截请求
  // event.request就是浏览器发出那个请求对象

  // 关键, 使用responseWith来控制如何控制响应这个请求.
  event.respondWith(
      caches.match(event.request) // 1.匹配请求路径
      .then(cachedResponse => {
        // cachedResponse要么是一个对象,要么就是undefined

        // 2.判断是否命中了缓存
        if(cachedResponse){
          return cachedResponse // 命中缓存直接返回
        }

        // 3.没有命中缓存,就请求网络更新
        return fetch(event.request)
        .then(networkResponse => {

          // 非有效的响应,不添加至缓存
          if(!networkResponse || networkResponse.status !== 200 || networkResponse.type !== 'basic'){
            return networkResponse
          }

          // 这里还有个问题, networkResponse 在Service Worker中只能读取一次,所以我们需要用到clone方法.
          // 创建networkResponse的副本用于缓存
          const responseToCache = networkResponse.clone();

          caches.open(CACHE_NAME)
          .then(cache => {
            // put接受两个参数, 一个request,一个response
            return cache.put(event.request, responseToCache)
          })


          return networkResponse
        })
      })
  )
})

```
