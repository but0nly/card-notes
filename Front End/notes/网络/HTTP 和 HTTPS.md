#面试题 

## 简单介绍

### HTTP
明文传输，数据在网络上是公开的，很容易被第三方窃听或者篡改。

### HTTPS
加密传输，在HTTP的基础上添加了`SSL/TLS`协议，确保了客户端和服务端之间传输时的**机密性**和**完整性**。

#### `SSL/TLS` 加密握手过程

| 步骤         | 发起方 | 消息内容                                                  | 目的                        |
| ---------- | --- | ----------------------------------------------------- | ------------------------- |
| 1.客户端问候    | 浏览器 | 1. 支持的`ssl/tls`的版本<br>2. 支持的加密套件<br>3. 客户端随机数（密钥生成材料） | 开启协商，告诉服务端自己能支持哪些加密方式。    |
| 2.服务端回应    | 服务端 | 1. 选定的`ssl/tls`版本<br>2. 选定的加密套件<br>3. 服务端随机数（密钥生成材料）  | 确定加密方案，提供另一半密钥生成材料        |
| 3. 发送证书    | 服务端 | 数字证书                                                  | **证明服务端身份**，提供客户端公钥。      |
| 4. 密钥交换    | 客户端 | 加密后的**预主密钥**（Pre-master-Secret）                       | 使用服务器证书上的公钥安全的传输密钥材料      |
| 5. 计算出回话密钥 | 双方  | 客户端随机数 + 服务端随机数 + **预主密钥**                            | 双方各自算出**对称回话密钥**          |
| 6.握手结束     | 双方  | 1. 模式切换信号（Change Cipher Spec）<br>2. 加密的`Finished`消息   | ** 切换到加密模式** ，并验证信息是否被篡改。 |

---

## 总结
### http
	- 明文传输，敏感信息容易被中间劫持
	- 对称加密
		- 一对key，都可以用于加密、解密
慢慢退出舞台
### https
	- 需要https证书
	- 原本的http + 加密
	- 非对称加密
		- 一个key负责加密， 一个key负责解密
现代浏览器已经开始强制https协议
