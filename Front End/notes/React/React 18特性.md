 主要特性有三个：
 - 并发模式
 - 并发工具
 - 全栈优化


### 并发模式
新的API，导入和方法调用都有变化。主要作用是让后台处理渲染任务而不在阻塞主线程。

原理：
==**时间切片**：将渲染工作拆分成可中断的小块，避免长时间阻塞主线程。==

1. 导入变化：`import ReactDOM from "react-dom/client"`
2. 方法调用变化：`ReactDom.createRoot(document.getElementById('root')).render(<App />)`

### 并发工具
- `useTranstion`:
区分两种类型的更新：
1. 紧急更新
2. 非紧急更新：使用`startTransition`，将函数标记为非紧急任务。


- `useDeferredValue`
可以延迟组件渲染，使其使用一个滞后的值，避免在用户快速输入时卡顿。


#### 两者区别

| 特性   | `useTransition`                 | `useDeferredValue`          |
| ---- | ------------------------------- | --------------------------- |
| 操作对象 | 状态更新（`setState`）                | Props                       |
| 控制权  | 手动控制                            | 自动控制，由React内部来决定            |
| 反馈机制 | 提供`isPending`状态，可以用来显示`loading` | 不直接提供`isPending`,需要切合其他来实现  |
| 最佳用例 | 路由切换；需要加载动画的点击操作                | 搜索过滤：将值传递给渲染耗时很重的子组件作为Prop； |

### Suspense
可以用与客户端和服务端。加速FCP和TTI。

|**知识点**|**机制**|**与并发的关联**|
|---|---|---|
|**Suspense**|声明式地指定 `fallback` UI，捕获组件抛出的 **Promise**。|允许组件在数据未就绪时“挂起”，而不是阻塞。|
|**流式 SSR**|服务器遇到 Suspense 边界时，**不等待**，先发送可用 HTML 和占位符。|**加速 FCP** (首次内容绘制)。|
|**选择性水合**|客户端优先水合用户点击区域，再在后台继续水合慢组件。|**加速 TTI** (可交互时间)，确保用户点击能立即得到响应。|
|**错误边界**|捕获组件抛出的 **Error**（例如数据加载失败）。|提供了 Suspense 机制下的必要错误处理和防护网（React 16 引入）。|
